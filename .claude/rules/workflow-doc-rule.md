# 研发流程文档编写规范规则
## 适用范围
项目内所有工作流产出文档，位于 `docs/workflow/` 目录下的全部md文件。

## 文档通用格式约束
1. 所有文档统一使用 Markdown 格式，文件名使用英文小写+横杠命名，禁止中文空格。
> 示例：test-case-login.md  不允许：登录测试用例.md
2. 每一份文档开头必须写明：迭代版本、文档创建人、创建时间、关联需求ID。
3. 文档中的需求点、验收标准、测试用例、风险项，必须可追溯，能够关联到上游阶段文档。
4. 测试用例固定结构：用例ID、模块、前置条件、操作步骤、预期结果、优先级、严重等级。
5. 风险清单必须包含：风险描述、影响程度、应对方案、负责人。

## 文档维护约束
1. 阶段交付物一旦评审基线锁定，**变更不允许直接修改原文档**，需要新增变更记录，回流需求阶段评估。
2. 文档更新时，更新文档修订记录，记录修改内容、修改时间。
3. 所有文档输出，语言简洁，避免模糊描述；验收标准、预期结果必须可验证，不能写“体验良好”这类无法验证的描述。
4. 文档完成后，输出交付物清单，作为阶段切换的依据。

## 文档存放约束
1. 需求文档：`docs/workflow/1-requirement/`
2. 交互&测试用例：`docs/workflow/2-interaction/`
3. 开发设计文档：`docs/workflow/3-design/`
4. 开发自测记录：`docs/workflow/4-code/`
5. 测试报告&bug清单：`docs/workflow/5-test/`
6. 发布归档&changelog：`docs/workflow/6-release/`
