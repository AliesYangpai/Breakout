# 研发工作流强制规则
## 核心流程约束
所有项目作业，**必须严格遵循固定研发流水线**：
需求 → 交互（同步输出测试用例） → 开发设计 → 开发编码 → 测试回归 → 版本发布

## 变更与Bug处理强制约束
1. 任何新增需求、需求变更、线上/测试发现的bug，**全部从需求源头进入评审环节**，不允许跳过需求评估直接进入交互、编码、修复等后续环节。
2. 不允许绕过流程直接写代码、直接修改交互、直接编写测试用例。任何改动，都需要先回流到需求阶段，评估范围、优先级、影响面，完成评审基线锁定，再继续向后流转。
3. 流程单向流转：上一阶段交付物未完成评审、未基线锁定，**禁止进入下一阶段工作**。
4. 若在任意阶段发现需求缺陷、范围变更、重大问题，必须停止当前阶段工作，回流至需求源头重新评审评估。

## 流程执行补充说明
1. 交互阶段必须同步产出测试用例，测试用例不能延后到编码完成之后才编写。
2. 只有当前阶段交付物评审通过，才允许切换到下一阶段skill。
3. 所有回流事件（bug、需求变更），都需要记录在需求文档中，纳入版本迭代范围管理。
