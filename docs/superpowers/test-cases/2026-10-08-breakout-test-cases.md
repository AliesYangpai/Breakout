## 1. 说明

### 1.1 覆盖方式标记

| 标记 | 含义 |
|------|------|
| ✅ 已自动化 | 已有 JUnit 单测覆盖（`app/src/test/.../core/`），给出测试方法名 |
| 🖐 手工 | 需真机/模拟器人工执行 |
| 🤖 建议补 UI 自动化 | 尚未实现，建议用 Compose UI Test 补充 |

### 1.2 优先级

- **P0**：核心玩法/关键路径，缺失则游戏不可用。
- **P1**：重要功能，影响体验或正确性。
- **P2**：一般/边界/视觉优化。

### 1.3 用例编号

`TC-<模块>-<序号>`，模块：FUNC 功能、ENT 实体碰撞、DIFF 难度、STATE 状态流转、ERR 错误边界、UI 界面、GEST 手势、FB 视觉反馈、SAVE 存档。

## 3. 详细测试用例

### 3.1 功能与玩法（FUNC）

#### TC-FUNC-001 经典玩法基本循环
- **优先级**：P0　**覆盖**：🖐 手工（底层逻辑 ✅ GameEngineTest 已覆盖碰撞/更新）
- **前置**：进入任一关
- **步骤**：拖动挡板接住球 → 观察球反弹击砖 → 重复直至砖被清空
- **预期**：球在挡板/墙/砖间反弹，砖被击碎消失，全程可玩、无卡死

#### TC-FUNC-002 共 10 个关卡
- **优先级**：P0　**覆盖**：✅ `LevelsTest.exactly_ten_levels`
- **步骤**：断言 `Levels.all.size == 10`
- **预期**：恰好 10 关，索引 0~9

#### TC-FUNC-003 普通砖 1 击摧毁
- **优先级**：P0　**覆盖**：✅ `EntitiesTest.brick_takeHit_reduces_hp`
- **预期**：`Brick(NORMAL).takeHit()` 后 `destroyed == true`

#### TC-FUNC-004 耐久砖多击摧毁
- **优先级**：P0　**覆盖**：✅ `EntitiesTest.brick_takeHit_reduces_hp`（2 击）、🖐 手工（3 击砖第 6 关起）
- **步骤**：第 4 关击打 2 击耐久砖；第 6 关击打 3 击耐久砖
- **预期**：2 击砖命中 1 次后不消失、命中 2 次消失；3 击砖命中 3 次才消失

#### TC-FUNC-005 硬砖不可摧毁
- **优先级**：P0　**覆盖**：✅ `EntitiesTest.brick_indestructible_never_destroyed`、🖐 手工
- **步骤**：第 7 关用球反复撞击灰色硬砖
- **预期**：硬砖永不消失，球每次反弹

#### TC-FUNC-006 过关目标（硬砖不计算）
- **优先级**：P0　**覆盖**：✅ `GameEngineTest.detectOutcome_ignores_indestructible`
- **预期**：场中只剩硬砖（无可破坏砖）时判定 `WON`；存在硬砖 + 可破坏砖时不为 `WON`

#### TC-FUNC-007 无道具掉落（YAGNI 反向验证）
- **优先级**：P2　**覆盖**：🖐 手工
- **步骤**：击碎大量砖块，观察是否有道具掉落物
- **预期**：无任何道具/掉落物出现（本版本范围外）

### 3.2 实体与碰撞（ENT）

#### TC-ENT-001 挡板水平移动与边界钳制
- **优先级**：P0　**覆盖**：✅ `GameEngineTest.movePaddle_clamps_to_field`
- **预期**：`movePaddleTo(x)` 将挡板中心钳制在 `[halfWidth, WIDTH-halfWidth]`

#### TC-ENT-002 球碰挡板角度反弹
- **优先级**：P0　**覆盖**：✅ `CollisionTest.paddle_center_hits_straight_up`、`paddle_edge_hits_sideways`
- **预期**：打中挡板中心→竖直上弹（vx≈0）；打中边缘→明显斜角反弹；速度大小守恒

#### TC-ENT-003 球碰左右上墙反弹
- **优先级**：P0　**覆盖**：✅ `CollisionTest.bounceOffWall_left_wall`、`bounceOffWall_top_wall`
- **预期**：碰左墙 vx 变正、碰右墙 vx 变负、碰上墙 vy 变正；位置被钳回边界内

#### TC-ENT-004 球掉底失命
- **优先级**：P0　**覆盖**：✅ `GameEngineTest.losing_ball_costs_life_and_resets_to_ready`
- **预期**：球越过底部 → `lives-1`、状态回 `READY`、球回挡板上方；`lives` 归零则 `LOST`

#### TC-ENT-005 球防卡死（最小垂直分量）
- **优先级**：P1　**覆盖**：✅ `CollisionTest.paddle_edge_hits_sideways`（速度守恒）、🖐 手工
- **步骤**：长时间游玩观察球是否进入接近水平的无限横飞
- **预期**：球始终保留足够垂直速度，不会水平横飞打不到砖

#### TC-ENT-006 球碰撞抖动防止（位置偏移）
- **优先级**：P1　**覆盖**：🖐 手工
- **步骤**：观察球擦边命中砖/墙的瞬间是否出现剧烈抖动或卡在边界
- **预期**：球命中后稳定弹出，无高频抖动、无卡墙

### 3.4 状态流转（STATE）

#### TC-STATE-001 主菜单 → 关卡选择
- **优先级**：P0　**覆盖**：🖐
- **步骤**：启动 app，点「开始游戏」
- **预期**：进入关卡选择页

#### TC-STATE-002 关卡选择 → 游戏中
- **优先级**：P0　**覆盖**：🖐
- **步骤**：点一个已解锁关卡
- **预期**：进入该关，球吸附在挡板上，状态 READY

#### TC-STATE-003 过关 → 下一关（第 1~9 关）
- **优先级**：P0　**覆盖**：🖐
- **步骤**：清空砖块，过关面板点「下一关」
- **预期**：进入下一关；下一关被解锁并写入存档

#### TC-STATE-004 过关 → 通关结算（第 10 关）
- **优先级**：P0　**覆盖**：🖐
- **步骤**：通关第 10 关
- **预期**：显示「恭喜通关」，按钮为「返回关卡选择」，**无**「下一关」按钮

#### TC-STATE-005 暂停 → 继续/重新开始/返回
- **优先级**：P0　**覆盖**：🖐（引擎层 ✅ `GameEngineTest.pause_and_resume`）
- **步骤**：游戏中点暂停，分别测试三个按钮
- **预期**：继续→恢复游戏；重新开始→重开当前关、生命归 3；返回→回关卡选择

#### TC-STATE-006 失败 → 重新开始/返回
- **优先级**：P0　**覆盖**：🖐
- **步骤**：耗尽 3 命触发失败面板，测试两按钮
- **预期**：重新开始→重开当前关、生命归 3；返回→回关卡选择

#### TC-STATE-007 状态竞态（非法跳转忽略）
- **优先级**：P1　**覆盖**：🖐
- **步骤**：过关/失败面板弹出瞬间，同时点击暂停或快速切屏
- **预期**：状态机只保留过关/失败状态，底层游戏输入不再响应，无崩溃

## 4. 测试缺口与建议

| 缺口 | 说明 | 建议 |
|------|------|------|
| UI/交互层无自动化 | `ui/` 包（GameScreen、BreakoutApp、关卡选择）无任何 UI 测试 | 补 Compose UI Test，覆盖 TC-UI-*、TC-GEST-*、TC-STATE-* 的状态跳转与点击 |
| 视觉反馈无自动化 | 砖颜色变化、消失等仅靠人工 | 用 Compose UI Test 断言渲染状态，或降级为人工验收 |
| 存档持久化无单测 | `SharedPreferencesProgressStore` 因依赖 Context 未测 | 用 Robolectric 或 instrumented test 补测 load/save |
| 切后台自动暂停无回归测试 | 该逻辑曾出过 Critical bug（39dcd66） | 用 instrumented test 模拟 ON_STOP 事件回归验证 |

---

## 5. 执行建议

1. **冒烟（P0 手工）**：每次发版前执行所有 P0 🖐 用例，约 10 分钟。
2. **全量回归（P0+P1）**：大版本前执行全部 🖐 用例。
3. **自动化**：优先补齐 §4 中「切后台自动暂停」与「UI 状态流转」两条自动化，因其风险最高、曾出过 bug。
