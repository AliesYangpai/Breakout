## 3. 经验与问题

| 类别 | 问题/经验 | 改进措施 |
|------|----------|---------|
| 技术 | 单球改多球后 `GameState.ball` → `balls: List<Ball>`，涉及引擎/渲染/测试多处联动 | 用纯函数拆分 `stepBalls`/`stepLasers` 等，JVM 单测直接覆盖，避免只靠 UI 验证 |
| 技术 | 道具叠加/幂等若用 List 会重复叠加 | 用 `Set<PowerUpType>` 天然去重，同种道具幂等 |
| 技术 | 随机掉落不可复现，测试不稳定 | 随机源抽象为可注入 lambda，测试确定性 |
| 流程 | 本次编码阶段误在 main 分支直接修改，违反分支管理规则 | 已及时纠正为 feature 分支；后续进入编码阶段前先确认在 feature 分支上 |
| 流程 | instrumented 测试长期未在真机跑通，掩盖了 KNOWN-001 基础设施问题 | 编码阶段即应尝试 instrumented test，而非留到测试阶段才发现 |
| 流程 | 需求变更（激光改两端发射）已按回流规则同步更新需求/交互/测试三处文档 | 回流机制有效，变更可追溯 |
