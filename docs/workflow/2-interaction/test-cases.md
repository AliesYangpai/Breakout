## 1. 说明

| 标记 | 含义 |
|------|------|
| ✅ 已自动化 | 已有 JUnit 单测或 instrumented test 覆盖，给出测试方法名 |

- **优先级**：P0（核心路径，缺失则不可用）/ P1（重要功能）/ P2（一般/边界/视觉）。

## 3. 详细测试用例

### 3.1 功能与玩法（FUNC）

#### TC-FUNC-001 经典玩法基本循环
- 模块：功能
- 前置条件：进入任一关
- 操作步骤：拖动挡板接住球 → 观察球反弹击砖 → 重复直至砖被清空
- 预期结果：球在挡板/墙/砖间反弹，砖被击碎消失，全程可玩、无卡死
- 优先级：P0　严重等级：致命　覆盖：🖐 手工（底层逻辑 ✅ GameEngineTest 已覆盖碰撞/更新）

#### TC-FUNC-002 共 10 个关卡
- 模块：功能
- 前置条件：无
- 操作步骤：断言 `Levels.all.size == 10`
- 预期结果：恰好 10 关，索引 0~9
- 优先级：P0　严重等级：致命　覆盖：✅ `LevelsTest.exactly_ten_levels`

#### TC-FUNC-003 普通砖 1 击摧毁
- 模块：功能
- 前置条件：无
- 操作步骤：断言 `Brick(NORMAL).takeHit()` 后 `destroyed`
- 预期结果：`destroyed == true`
- 优先级：P0　严重等级：致命　覆盖：✅ `EntitiesTest.brick_takeHit_reduces_hp`

#### TC-FUNC-004 耐久砖多击摧毁
- 模块：功能
- 前置条件：进入第 4 关（2 击砖）、第 6 关（3 击砖）
- 操作步骤：分别击打 2 击耐久砖、3 击耐久砖，观察消失时机
- 预期结果：2 击砖命中 1 次不消失、命中 2 次消失；3 击砖命中 3 次才消失
- 优先级：P0　严重等级：致命　覆盖：✅ `EntitiesTest.brick_takeHit_reduces_hp`（2 击）、🖐 手工（3 击砖）

#### TC-FUNC-005 硬砖不可摧毁
- 模块：功能
- 前置条件：进入第 7 关
- 操作步骤：用球反复撞击灰色硬砖
- 预期结果：硬砖永不消失，球每次反弹
- 优先级：P0　严重等级：致命　覆盖：✅ `EntitiesTest.brick_indestructible_never_destroyed`、🖐 手工

#### TC-FUNC-006 过关目标（硬砖不计算）
- 模块：功能
- 前置条件：无
- 操作步骤：断言 `detectOutcome` 对仅剩硬砖 / 硬砖+可破坏砖两种场
- 预期结果：仅剩硬砖判定 `WON`；存在硬砖 + 可破坏砖时不为 `WON`
- 优先级：P0　严重等级：致命　覆盖：✅ `GameEngineTest.detectOutcome_ignores_indestructible`

#### TC-FUNC-007 道具掉落已纳入本期范围
- 模块：功能
- 前置条件：进入任一关
- 操作步骤：击碎可破坏砖块
- 预期结果：按配置概率掉落道具（详见 TC-PROP-001~003），不再为空
- 优先级：P2　严重等级：轻微　覆盖：🖐 手工

### 3.2 实体与碰撞（ENT）

#### TC-ENT-001 挡板水平移动与边界钳制
- 模块：实体
- 前置条件：无
- 操作步骤：调用 `movePaddleTo(x)` 于超出边界/边界内多种 x
- 预期结果：挡板中心钳制在 `[halfWidth, WIDTH-halfWidth]`
- 优先级：P0　严重等级：致命　覆盖：✅ `GameEngineTest.movePaddle_clamps_to_field`

#### TC-ENT-002 球碰挡板角度反弹
- 模块：实体
- 前置条件：无
- 操作步骤：断言打中挡板中心 / 边缘两种情况的速度
- 预期结果：中心→竖直上弹（vx≈0）；边缘→明显斜角反弹；速度大小守恒
- 优先级：P0　严重等级：致命　覆盖：✅ `CollisionTest.paddle_center_hits_straight_up`、`paddle_edge_hits_sideways`

#### TC-ENT-003 球碰左右上墙反弹
- 模块：实体
- 前置条件：无
- 操作步骤：断言球碰左墙 / 碰右墙 / 碰上墙后的速度分量
- 预期结果：碰左墙 vx 变正、碰右墙 vx 变负、碰上墙 vy 变正；位置钳回边界内
- 优先级：P0　严重等级：致命　覆盖：✅ `CollisionTest.bounceOffWall_left_wall`、`bounceOffWall_top_wall`

#### TC-ENT-004 球掉底失命
- 模块：实体
- 前置条件：球越过屏幕底部
- 操作步骤：断言失命后的状态迁移
- 预期结果：`lives-1`、状态回 `READY`、球回挡板上方；`lives` 归零则 `LOST`
- 优先级：P0　严重等级：致命　覆盖：✅ `GameEngineTest.losing_ball_costs_life_and_resets_to_ready`

#### TC-ENT-005 球防卡死（最小垂直分量）
- 模块：实体
- 前置条件：长时间游玩
- 操作步骤：观察球是否进入接近水平的无限横飞
- 预期结果：球始终保留足够垂直速度，不会水平横飞打不到砖
- 优先级：P1　严重等级：一般　覆盖：✅ `CollisionTest.paddle_edge_hits_sideways`（速度守恒）、🖐 手工

#### TC-ENT-006 球碰撞抖动防止（位置偏移）
- 模块：实体
- 前置条件：无
- 操作步骤：观察球擦边命中砖/墙瞬间是否剧烈抖动或卡在边界
- 预期结果：球命中后稳定弹出，无高频抖动、无卡墙
- 优先级：P1　严重等级：一般　覆盖：🖐 手工

## 4. 测试缺口与建议

| 缺口 | 说明 | 建议 |
|------|------|------|
| 视觉反馈无自动化 | 砖颜色变化、消失等仅靠人工 | 用 Compose UI Test 断言渲染状态，或降级为人工验收 |
| 状态流转部分仅手工 | TC-STATE-003/004/006 等依赖完整游戏进程 | 用 instrumented test 注入状态或补 UI 状态跳转测试 |
| 存档持久化跨进程无自动化 | 杀进程重开仅手工 | 用 Robolectric（已覆盖 save/load round-trip）补充跨进程语义 |
| 道具随机掉落需确定性测试 | 随机概率难断言 | 注入固定随机源/种子，使掉落可确定化再断言 |
| 激光/掉落物视觉反馈 | 激光飞行、掉落物下落渲染 | 用 Compose UI Test 断言渲染状态，或降级为人工验收 |

## 5. 执行建议

1. **冒烟（P0 手工）**：每次发版前执行所有 P0 🖐 用例，约 15 分钟。
2. **全量回归（P0+P1）**：大版本前执行全部 🖐 用例。
3. **自动化**：`core`/`data` 层已有较完整 JUnit + Robolectric 覆盖；UI 层已有 navigation / 输入 / 自动暂停 instrumented test，见 §1.1 ✅ 标记。道具/激光/多球需在编码阶段补齐 `GameEngineTest` 单测。
